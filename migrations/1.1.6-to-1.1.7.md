# 1.1.6 → 1.1.7

## why

准备发行包一直只从官方地址匿名下载，这条路不能加星，也不能在用户账号下建副本。用户希望下载成功后，如果本机已经登录 GitHub，就顺手做这两件事；没登录只提示，不挡安装。下载源不能改成账号副本。

## from

- PH 1.1.6、Schema 1.1.1、十个必需 Skill；用户入口只有 `ph-init`，已装旧版由同一会话按 merge-update 步骤升级。
- `ph_release.py prepare` 只做 `git ls-remote` 和浅层 `git fetch`，清掉凭据助手，禁止交互登录。stdout JSON 只有 `version` `tag` `commit` `source` `root`。
- 检查 / 同步保持离线，不重新 prepare。

## to

- PH 1.1.7，Schema 保持 1.1.1、十个 Skill、adapter mode 与安装内核命令不变。
- 官方下载地址不变。准备成功后附加加星和建账号副本：本机已登录才做，失败只写提示，退出码仍为 0。
- 新增 `ph_release.py support`：只做加星和建副本，不再下载。用旧脚本第一次拉到本版时，读发行根 Skill 后补跑这一步。
- 存量项目只合并这些说明和 Skill 正文，不改业务文档、不重跑文档补全、不自动 finalize。

## affected

分两类目标处理；已安装项目的状态写入 `.agents/updates/1.1.7/state.json`，证据记录到 `report.md`。跨版本升级读取整条迁移链，进度目录用最终目标版本。

### 已安装 PH 的存量项目（1.1.6 及更早）

- 升级仍用发行根 `ph_merge_update.py`，由 **ph-init 会话**读发行根 `assets/scaffold/.agents/skills/ph-merge-update/SKILL.md` 执行。禁止重跑 `init --apply`，禁止 `init --adopt-plan`。
- 按下列迁移项合并准备成功后的提示口径，以及相关 Skill / eval 的说明。保留项目对这些文件的本地定制，不整树强盖，不重写业务正文。
- 本会话若刚用旧脚本 prepare，用发行根补跑 `python3 <release-root>/scripts/ph_release.py support`。检查 / 同步仍然离线，不为了加星上网。

### 未安装 PH 的存量仓库

无需本项：首次接入直接用 1.1.7 的准备脚本，下载成功后按本机是否已登录附加加星和建副本。

### `prepare-star-fork`

- 合并根 `SKILL.md` 与 `ph-merge-update` 中“准备成功后转告脚本提示、没登录不拦安装、不从副本拉正式包”的句子。
- evals 只补：准备成功后把脚本提示转告用户；检查 / 同步不重新上网加星。
- 不同步业务 Wiki、意图正文、访谈原话或项目已填约束。不因本项重跑文档补全。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、业务事实、用例源文件，以及 subagent 已合并的 Wiki / 规范产物。
- 十 Skill 契约、Schema 1.1.1 与原 adapter mode；脚本安装字段、覆盖报告五态、四类整合内部标题。
- 官方下载地址、匿名 git 下载、失败则关的版本 / 网络策略。
- 未完成升级的 `.agents/updates/<ver>/` 进度：已落地项不重做。

## conflict

- 项目明确禁止给外部仓库加星或在个人账号建副本：停止受影响项，标 `blocked`，记录原约定；不得擅自改项目已写的对外说明。加星失败本身不构成升级失败。
- 仓内版本新于本包：内核阻断，不降级、不改磁盘。
- 路径不安全、根 `AGENTS.md` 无 canonical、受跟踪 worktree 等继续 fail-closed。备份按项目授权保留，不使用 rm。

## verify

1. 已安装项目：`prepare-star-fork` 有真实 evidence，必需项无 pending / blocked；已填字段与无关业务正文仍保留；用本版发行根执行 `ph_merge_update.py verify`、`finalize`（经授权 `--apply`），再按原 mode 常规 `check`。
2. 无登录时 prepare 成功，标准错误有白话提示，标准输出仍是原来五个字段；加星或建副本失败时退出码仍为 0，可以继续安装或升级。
3. verify / finalize 只检查结构与状态，不证明语义正确；重复执行不重复插入，失败保持 in_progress，未完成迁移项不得推进 `template_version`。
