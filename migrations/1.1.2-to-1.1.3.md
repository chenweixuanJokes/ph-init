# 1.1.2 → 1.1.3

## why

初始化不能只交付占位目录。存量项目需要在 init 会话中，按真实代码和技术栈、实时官方资料补齐 Wiki 与规范；已有同名 docs 必须保留。补全成果属于项目内容，不能在下一次升级中被模板覆盖。

## from

- PH 1.1.2、Schema 1.1.1、十个必需 Skill；init 只复制模板，已有同名 docs 内容不同会阻断。
- 规范与 Wiki 可能仍有占位，也可能已由项目填写或拆成专文，必须按实态识别。
- 从正式 1.1.1 或更早布局出发须读取整个迁移链，先满足意图最终态；不假设 1.1.2 已有正式 tag。

## to

- PH 1.1.3，Schema 保持 1.1.1，仍为十个 Skill，adapter mode 不变。
- 首次 init 的内核保留已有安全普通 docs，缺失才安装。内容审阅与补全由会话编排，内核不联网生成正文。
- 规范新增初始化补全、安全配置、构建发布运维细节；Wiki 模板补证据与知识覆盖提示。
- 既有项目升级仅合并此次指导内容、缺失章节和索引，不自动重建业务 Wiki、不重新选择项目栈。

## affected

按下列顺序处理，状态写入 `.agents/updates/1.1.3/state.json`，记录证据到 `report.md`。跨版本时使用最终目标版本的进度目录。

### `init-docs-workflow`

从本次固定发行根合并项目已装 `.agents/skills/ph-init/` 的 `SKILL.md`、`scripts/ph_init.py`、release 元数据、迁移材料、evals 与内嵌 scaffold；保留该 Skill 的本地定制，不整树强盖。合并 `.agents/skills/ph-merge-update/SKILL.md` 的本次边界。

确认入口包含：实际栈盘点、只读 dry-run、保留同名 docs、安装后分阶段 subagent 补全、实际版本公网资料、失败续做及分别报告安装/文档结果。check/sync 仍离线且不生成 docs。不要对目标项目运行 init --apply 验证。

### `docs-guidance`

按段落合并以下 PH 指导，不把本次发行模板当成项目正文：

- `docs/约束规范/工程规范/`：新增 `初始化与文档补全.md`、`安全与配置.md`、`构建发布与运维.md`；补 Git/通知授权与文档治理的 Wiki 同步、纠正、问答边界。
- 前端、后端、测试汇总文：补缺少的规范说明、证据要求与用例索引结构。已拆专文的项目在现有落点合并，保留已填写命令、例外与技术栈，不复制第二套规则。
- `.agents/AGENTS.md` 与各级 README：只补摘要和有效深链。内嵌 scaffold 中更新完整新模板；项目根 Wiki 页面只补确实缺失的必要元数据/证据提示与索引，不替换已填事实。

新增文件遇到同名定制文时按内容合并或链接到等价落点。若完全等价可 `not_applicable`，须列出覆盖路径与章节，不能只写“已有”。

### `docs-project-preserve`

盘点已填 Wiki、规范、用例入口、项目配置与意图/记忆，记录保留证据和文档缺口。**无需存量业务正文迁移**：此版本不改变其路径或语义，不要求所有占位立刻填完才能升级。

记录“待后续补全”不等于完成那次补全。完整代码调研、全网研究、Wiki 重建与建议采纳不属于普通升级；只有用户另行授权相关补全范围时才执行。同意升级不是授权改业务代码、创建意图或替换项目规则。

本项完成意味着保留审阅已完成：有改动的混合文列出保留段落及差异，无关正文可用前后内容摘要/哈希证明未变。不能仅凭脚本 verify 成功标 applied。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、环境边界、业务事实与用例源文件。
- subagent 曾生成并已合并的 Wiki/规范也属于项目定制，不可当作可重生成的模板丢弃。
- Wiki owner/核验历史、ADR 决策依据、访谈原话、意图编号、记忆原件及其效力。
- 十 Skill 契约、Schema 1.1.1 与原 adapter mode。不新增 Wiki 三 Skill 或记忆纠正 Skill，不恢复已完成目录。

## conflict

- PH 新规则与项目明确约定冲突、同名文档用途不同且无法兼容、来源不明：停止受影响项，标 `blocked` 并记录原内容和需裁决事项。
- 不覆盖定制、不自动采纳外部建议、不把 Kong/Eureka/Apollo 当必装组件。
- 路径不安全、根 AGENTS 没有 canonical、受跟踪 worktree 等继续 fail-closed；不得为通过安装临时挪走阻断文件。
- 中断后对照磁盘恢复；已落地章节不重复插入，未解决项不能记 applied。备份按项目授权保留，不使用 rm。

## verify

1. 三项都有真实 evidence，必需项无 pending/blocked；README 深链有效，已填字段与无关业务正文仍保留。
2. 检查项目已装 ph-init 包携带新增指导文档，且保留同名 docs 的行为已合并；必要时只在隔离临时 Git 仓验证安装，绝不重装目标。
3. 分别记录“升级适配结果”和“文档内容补全状态”。有待核实事实不谎报文档已补全；未完成迁移项则不能推进版本。
4. 用本次发行根执行 `ph_merge_update.py verify --repo <target>`、`finalize --repo <target>`；经授权 `finalize --apply` 后按原 mode 常规 check。
5. verify/finalize 只检查结构与状态，不证明语义正确。重复执行不重复插入，失败保持 in_progress，不因版本字段已写入而跳过验收。
