# 1.1.8 → 1.1.9

## why

本批合并三个互不依赖的改动。

创建隔离工作区时，用户已经明确表达了创建意图，旧流程仍要求再次确认来源分支、任务分支以及是否实际创建，产生了不必要的往返。本版把正常决策留给代理：以主工作区当前分支为源，结合任务语义和项目命名规则确定任务分支，安全检查通过后直接创建。

适配层改为工具中立：此前 PH 按厂商逐一铺镜像，`.codex/skills/ph-*` 与 `.claude/skills/ph-*` 并列。实际三工具拓扑中只有 Claude Code 需要厂商入口：约束与技能的 canonical 固定在 `.agents/`，根 `AGENTS.md` 是通用入口；Claude Code 经 `CLAUDE.md` 与 `.claude/skills/` 适配层接入；Codex 与 OpenCode 原生读取 `AGENTS.md` 与 `.agents/skills`，`.codex/skills` 镜像纯属冗余维护面。本批退役 Codex 侧镜像，manifest 不再声明 `adapters.codex_skills`。

官方 GitHub 仓库由 `chenweixuanJokes/ph-init` 更名为 `chenweixuanJokes/project-harness`，产品对外名称统一为 Project Harness。仓库名与产品名变化不改变安装入口和技能命名：入口仍是 `ph-init`，十个必需 Skill 仍是 `ph-*`，用户级安装路径仍是 `~/.agents/skills/ph-init`。新版运行时改从新地址下载发行包；旧地址经 GitHub 重定向继续有效，旧来源字段保留兼容含义，存量项目不必改写任何来源值。

## from

- PH 1.1.8，十个必需 Skill，项目清单只有 `template_version`，不含 `schema_version`。
- 官方源是旧地址 `https://github.com/chenweixuanJokes/ph-init.git`：运行时只有 `FIXED_SOURCE` 一个固定源常量，`release.json.repository`、`receipt.source`、`state.source.repository` 都记录旧地址；仓库、产品与安装入口都以 ph-init 相称。
- manifest `adapters` 声明四个适配：`root_agents`、`claude_entry`、`claude_skills`、`codex_skills`（portable 为 `mirror_tree`，symlink 为 `symlink`，include `ph-*`）。
- 已装项目存在 `.codex/skills/ph-*`：portable 模式是完整受管镜像目录，symlink 模式是指向 `../../.agents/skills/<name>` 的相对软链；`ph_init.py` 的 sync/check/infer 仍创建、校验并重建它们。
- `ph-worktree-enter` 要求先向用户确认新分支或已有分支，再展示计划并询问是否真正创建。
- worktree 脚本实际已经从主工作区当前 attached branch 读取 `sourceBranch`，并在创建新 worktree 时使用 `git worktree add -b` 一次完成新分支和 linked worktree 的创建。

## to

- PH 1.1.9，版本契约和十个必需 Skill 不变；manifest `adapters` 只剩 `root_agents`、`claude_entry`、`claude_skills`，`codex_skills` 随 finalize 移除。
- 三工具拓扑：canonical `.agents/` + 根 `AGENTS.md` 通用入口；Claude Code 用 `CLAUDE.md` 与 `.claude/skills/` 适配层；Codex、OpenCode 原生读取 `AGENTS.md` 与 `.agents/skills`，不铺任何厂商目录。
- adapter mode 保留不变：portable/symlink 只作用于剩余入口（根 `AGENTS.md`、`CLAUDE.md`、`.claude/skills/`），升级不迁移模式、不自动转换。
- `auto` 模式仅用于新装：安装命令显式缺省时先探测软链能力，可用优先 symlink、失败回落 portable；该选择只在 apply 阶段落定并写入具体模式，不作为清单值，也不适用于已装项目——升级沿用项目已声明或可推断的原模式。
- 存量项目升级时安全退役 `.codex/skills/ph-*`：`verify` 逐项分类，`finalize --apply` 才把可证明受管的条目落到 `.agents/archived/<日期>-pre-update/codex-skills/<name>`（项目内归档，可恢复）；portable 镜像与降级链接文件整项移动，活软链不能移入 `.agents`（canonical 树必须无链接），改为解除链接并在归档处留下含原链接目标的记录文件。dry-run 与 verify 不移动、不写任何文件。
- 退役证据契约：symlink 条目必须是指向 canonical 的正确相对软链；portable 镜像必须与当前 canonical 逐字节一致（退役无损），或与 git HEAD 记录的迁移前 canonical 快照逐字节一致且镜像自身无漂移。形态异常、目标异常、内容漂移或无法证明的一律阻断并原地保留，交语义迁移阶段或用户处置；非 `ph-*` 条目（如 `.codex/skills/my-tool`）永不触碰。
- worktree 行为：用户明确要求创建 worktree 时，来源默认取主工作区当前分支和当前提交，不再询问或切换来源分支；任务分支由代理结合任务语义与仓库分支规则自行确定，用户未指定时默认创建新的、未占用的英文任务分支，名称冲突时代理自行换一个清晰的新名称，不二次问询；只有用户明确要求复用某个已有分支时才使用 `--existing`；正常计划不再二次问询，工作区不干净、分支不存在或被占用、路径不安全、验收命令可疑等异常仍保持阻断。
- 官方仓库更名为 `https://github.com/chenweixuanJokes/project-harness.git`，产品名统一为 Project Harness；技能名、安装路径、目录名保持 `ph-init` / `ph-*` 不变，不迁移用户级入口、不重建技能目录。
- 新版运行时以新地址（`DOWNLOAD_SOURCE`）下载发行包；`FIXED_SOURCE` 旧地址与 `release.json.repository`、`receipt.source`、`state.source.repository` 在 1.x 保留兼容含义：旧地址经 GitHub 重定向指向同一仓库，1.1.8 及以后入口按旧地址 prepare 仍能取到新包；存量来源值不要求改写，也不当作错误。

- 合并 `.agents/AGENTS.md`、`docs/约束规范/工程规范/Git与并行开发.md`、`docs/约束规范/工程规范/对用户提问.md` 与 `docs/项目Wiki/开发指南.md` 中对应说明。
- 更新 `ph-worktree-enter` 行为样例：明确给出分支时直接使用；未给出时由代理自行生成；正常计划不再二次确认。
- 合并 `.agents/skills/ph-merge-update/SKILL.md` 及行为样例中的 1.1.9 迁移项和跨版本入口说明，确保 1.1.8 项目可直接更新，更早项目可经已发布 v1.1.8 工具取得本版。
- 无需修改 `.agents/ph.json` 的 worktree 配置结构、`ph.schema.json` 或 session 格式；底层脚本仍接收代理已经确定的 `--branch`。
- 项目内 ph-init runtime、迁移索引及发行材料更新为 1.1.9；剩余入口按原 adapter mode 同步受管副本或相对链接。

### `tool-neutral-adapters`

- 项目 `.agents/ph.json`：`adapters.codex_skills` 仅在 finalize 验收通过后随 `template_version=1.1.9` 一起移除，中途保持原值；`.agents/ph.schema.json` 更新为不再定义或接受该适配的 1.1.9 契约，旧四适配清单只作为迁移输入读取。
- 退役由升级工具自动完成：`inspect` 报告 `.codex/skills/ph-*` 分类结果；`verify` 阻断不可证明条目；`finalize --apply` 移动可退役条目到 `.agents/archived/<日期>-pre-update/codex-skills/` 并在返回结果中记录每个移动，中断后可识别已归档并幂等续做（复用同一日期目录）。
- 合并 `ph-init` / `ph-merge-update` Skill、README 与工程规范中三工具拓扑、`auto` 仅新装、Codex 侧退役的说明；新装不再创建 `.codex/`。

- `.codex/skills` 目录本身可能残留为空目录，属预期，可由用户自行清理；工具不删目录、不碰非 `ph-*` 内容。

### `repository-rename`

- 合并 `ph-init` / `ph-merge-update` Skill 中的官方源和品牌说明：产品名 Project Harness，正式链接指向新仓库 `project-harness`；旧地址只作为兼容与历史来源出现。项目文档如有引用官方源地址，一并更新为新地址。
- 项目内 ph-init runtime 与发行材料随本批更新：下载改走新地址（`DOWNLOAD_SOURCE`）；`FIXED_SOURCE` 与 `release.json.repository` 在 1.x 保留旧地址的兼容含义。
- `receipt.source` 与历史 `.agents/updates/<ver>/state.json` 的 `source.repository` 等存量来源值不改写；已发布迁移说明与 Changelog 中的旧地址保持原样。
- 用户级入口目录 `~/.agents/skills/ph-init` 与项目内 `.agents/skills/ph-*` 不因更名迁移或重建；本次升级涉及的 state 登记新增本项，旧地址来源值不手改。

## conflict

- 项目规则明确要求创建 worktree 前必须由用户指定或批准来源分支、任务分支或最终创建动作：本项与项目规则冲突，停止对应段落合并并请用户决定，不擅自削弱项目规则。
- 项目分支命名规则不足以生成合法英文名称，且任务语义也无法形成清晰名称：停止并说明缺失信息；不得用随机无意义名称掩盖问题。
- 项目本地定制的 `ph-worktree-enter` 改变了脚本参数、session 契约或退出流程：保留定制并标记冲突，不能只替换 Skill 文案后假称升级完成。
- 项目工具或规则显式依赖 `ph.json` 的 `adapters.codex_skills` 字段或 `.codex/skills/ph-*` 路径：停止 `tool-neutral-adapters` 对应段落，标 `blocked` 并记录依赖位置请用户决定；不得擅自改项目工具，也不得为兼容保留双份镜像。
- `.codex/skills/ph-*` 出现形态异常（普通文件、junction、嵌套软链）、软链目标不是 canonical、镜像内容漂移或无法证明受管：该条目原地保留并整体阻断 verify，由语义迁移阶段人工归档或补齐证据（提交迁移前状态）后重试；不得凭 `ph-*` 前缀猜测放行。
- 任何工作区不干净、分支占用、路径重定向、锁冲突或验收命令风险仍按原流程阻断；取消正常二次确认不等于取消异常门禁。
- 项目规则或用户要求把技能名、安装路径一并改成 `project-harness` / `project-*`：与本项名称分离设计冲突——技能与入口保持 `ph-init` / `ph-*`，不迁移用户级入口、不重命名技能目录；坚持改名时停止本项并请用户决定，不擅自重命名。

## verify

1. `worktree-auto-branch`、`tool-neutral-adapters`、`repository-rename` 均有真实 evidence，必需项无 pending / blocked；项目已填分支规则和无关正文仍保留。
2. `ph-worktree-enter` 明确：来源使用主工作区当前分支；代理自行确定新任务分支；用户明确创建后正常路径不再二次询问；复用已有分支只响应用户明确要求。
3. `对用户提问.md` 不再包含“确认后我才会真正创建”以及正常创建的新分支/已有分支选择题；异常处理问句仍保留。
4. 升级完成后项目内无 live 的 `.codex/skills/ph-*`：portable 镜像整目录归档到 `.agents/archived/<日期>-pre-update/codex-skills/<name>`，symlink 条目在归档处留有含原链接目标的记录文件；`.codex/skills/my-tool` 等非 `ph-*` 内容逐字节保留；manifest 无 `adapters.codex_skills` 且 `template_version=1.1.9`。
5. 工具自动退役只发生在 `finalize --apply`：dry-run 与 verify 不移动、不写 `.agents/archived/`；被阻断条目原地保留。语义合并阶段如需人工归档，先核对迁移前摘要、保留原文并记录 evidence。重复 finalize 不重复归档；软链接记录写入后中断，可在核对记录完全一致后继续，其他归档碰撞仍阻断。自动退役结果写入 state 的 `retired_codex`，含名称、归档路径、形态和依据。
6. 官方源说明已按更名合并：项目内 Skill 与文档的正式链接指向新仓库 `project-harness`；`receipt.source`、state 的 `source.repository` 与历史升级记录中的旧地址未被改写，也不被当作错误；用户级入口仍在 `~/.agents/skills/ph-init`，技能目录仍为 `ph-*`。
7. 从 PH 1.1.8 升级时读取本迁移项并按原 adapter mode 完成 verify/finalize；完成后 `template_version=1.1.9`，项目清单仍无 `schema_version`。
8. 从 PH 1.1.7 及更早升级时，先用已发布 `v1.1.8` 工具完成一次性入口切换，再由该工具准备并固定 `v1.1.9`，读取完整迁移链后升级；不能用旧入口直接读取 1.1.9，也不能拿开发分支冒充正式版。
9. 重复 inspect/finalize 不重复插入规则；失败保持 in_progress，不提前推进项目版本。
