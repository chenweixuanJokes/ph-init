# 1.1.4 → 1.1.5

## why

1.1.4 已能把存量未装仓库用旧内容接入，但用户对已经初始化的旧项目再说「初始化 PH」时，要么撞上不透明的版本错误，要么被要求另开 `ph-merge-update`。本批把对外入口收成一个：`ph-init` 会话自己分流，已装旧版在本会话按发行根的 merge-update 步骤做完。两套内核仍分开，不把 inspect / finalize 并进 `ph_init.py`，也不用 `init --apply` 盖旧项目。

## from

- PH 1.1.4、Schema 1.1.1、十个必需 Skill；已装项目升正式版对外分流到 `ph-merge-update`。
- `init --adopt-plan` 遇到已有 `.agents/ph.json` 退出 1，提示 `use ph-merge-update`。
- 已装旧版跑普通 `init` 时，`resolve_mode` 会先走 `validate_manifest`，报 `template_version must be '1.1.4'`，不说明本会话接着做什么。
- `check` / `sync` 用已装内核，不升版本；同版重跑 init 保留定制 canonical。

## to

- PH 1.1.5，Schema 保持 1.1.1、十个 Skill、adapter mode 不变。
- 用户只说「初始化 PH」「安装 harness」「升级 PH」都走 `ph-init`。本会话 `prepare` 之后分流：没装走现行空仓安装 / adopt；已装且版本旧于发行根，停 `init --apply`，按发行根 merge-update Skill 做完 inspect → 语义合并 → verify → finalize；已装且已是发行根版本，不升级。
- `ph_init.py` 的 `init` 在 `resolve_mode` 之前：正规 `.agents/ph.json` 的 `template_version` ≠ 本包版本 → 退出 1，`error=` 写清仓内版本、本包版本、禁止 `init --apply` / `--adopt-plan`，并给出本会话接着要跑的 `ph_merge_update.py inspect` 命令。仓内比本包新同样 fail-closed，不降级。
- `ph_init.py` 不 import、不 subprocess `ph_merge_update.py`，不自动改 `template_version`。`ph-merge-update` 目录保留，给会话当升级步骤用，不再当作必须另开的对外分流。
- `--adopt-plan` 已装拒绝可带上 from/to，语义不变。`check` / `sync` 仍用已装内核，不升版本。

## affected

分两类目标处理；已安装项目的状态写入 `.agents/updates/1.1.5/state.json`，证据记录到 `report.md`。跨版本升级读取整条迁移链，进度目录用最终目标版本。

### 已安装 PH 的存量项目（1.1.4 及更早）

- 升级仍用发行根 `ph_merge_update.py`，由 **ph-init 会话**读发行根 `assets/scaffold/.agents/skills/ph-merge-update/SKILL.md` 执行。禁止重跑 `init --apply`，禁止 `init --adopt-plan`。不要求用户另开技能。
- 按下列迁移项合并项目已装 `.agents/skills/ph-init/`（`SKILL.md`、`scripts/ph_init.py`、evals、指引）与 `ph-merge-update` 的入口说明，保留项目对这些 Skill 的本地定制，不整树强盖。

### 未安装 PH 的存量仓库

无需本项：首次接入仍用 1.1.4 起的 adopt 流程，不走 merge-update。

### `init-unified-entry`

- 合并根 `SKILL.md`：已装项目的安装、检查、同步、升正式版都由本 Skill 接；工作流第 1 步按仓内版本分流；完成标准要求已装旧版未走 `init --apply`，升级在本会话用发行根 `ph_merge_update.py` 做完，未另开技能、未自动 finalize。
- 合并 `scripts/ph_init.py`：`init` 对版本不匹配的已装目标 fail-closed，并写清本会话接着的 inspect 命令。
- 合并 `assets/scaffold/.agents/skills/ph-merge-update/SKILL.md`：改成给 ph-init 会话执行的步骤，不再把未安装仓库推回另一个入口当互斥分流。
- 同步合并指引、根 README、canonical 导航、`evals/evals.json`（含已装旧版用户说「初始化 PH」的场景）。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、业务事实、用例源文件，以及 subagent 已合并的 Wiki / 规范产物。
- 十 Skill 契约、Schema 1.1.1 与原 adapter mode；`ph-merge-update` 目录与必需 Skill 清单。
- 已安装同版项目重跑 init 时已定制的 canonical 原文。
- 未完成升级的 `.agents/updates/<ver>/` 进度：已落地项不重做。

## conflict

- PH 新入口说明与项目明确约定「必须另开 merge-update Skill」冲突：停止受影响项，标 `blocked`，记录原约定与需裁决事项；不得擅自删掉项目定制。
- 仓内版本新于本包：内核阻断，不降级、不改磁盘。
- 路径不安全、根 `AGENTS.md` 无 canonical、受跟踪 worktree 等继续 fail-closed。备份按项目授权保留，不使用 rm。

## verify

1. 已安装项目：`init-unified-entry` 有真实 evidence，必需项无 pending / blocked；已填字段与无关业务正文仍保留；用本版发行根执行 `ph_merge_update.py verify`、`finalize`（经授权 `--apply`），再按原 mode 常规 `check`。
2. 夹具 `template_version=1.1.4`，用 1.1.5 内核跑 `init`（含 `--apply`）退出 1；stderr 含 `ph-merge-update`、`1.1.4`、`1.1.5`、`inspect`；磁盘版本和定制文件不变。
3. 同版重跑仍保留定制 canonical；已装拒绝 adopt；check/sync 不升版本。
4. verify / finalize 只检查结构与状态，不证明语义正确；重复执行不重复插入，失败保持 in_progress，未完成迁移项不得推进 `template_version`。
