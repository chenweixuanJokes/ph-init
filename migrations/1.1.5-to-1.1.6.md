# 1.1.5 → 1.1.6

## why

1.1.5 已经把安装、检查、同步和升级收成一个入口，但规范把内部工序词写进了代理步骤。代理提问时几乎原样甩给用户，于是出现 `dry-run`、`adopt-plan`、`canonical`、`blocked`、`status_dir` 这类词。本批只改用户听得见的问句、选项和一句解释，不改脚本字段、覆盖报告枚举或四类整合内部标题。

## from

- PH 1.1.5、Schema 1.1.1、十个必需 Skill；用户入口只有 `ph-init`，已装旧版由同一会话按 merge-update 步骤升级。
- 何时该问、一轮一事、冲突不擅自拍板已经写在各流程正文里；对用户怎么问几乎没有统一口径，只有意图与访谈里的个别白话示例。
- 接入预检、写入授权、升级确认、意图歧义、隔离工作区与记忆核验等门禁，步骤里直接使用内部字段名和脚本参数。

## to

- PH 1.1.6，Schema 保持 1.1.1、十个 Skill、adapter mode 与内核命令不变。
- 新增 `docs/约束规范/工程规范/对用户提问.md`：先说要用户决定什么，问句和选项用日常用语；内部名字只留在报告和代理笔记。
- 接入、升级、意图、并行工作区、记忆各门禁补对用户说的问句模板。报告四类标题、`ph.json` 字段、脚本参数、覆盖报告五态保持原名。
- 存量项目只合并这些说明和 Skill 正文，不改业务文档、不重跑文档补全、不自动 finalize。

## affected

分两类目标处理；已安装项目的状态写入 `.agents/updates/1.1.6/state.json`，证据记录到 `report.md`。跨版本升级读取整条迁移链，进度目录用最终目标版本。

### 已安装 PH 的存量项目（1.1.5 及更早）

- 升级仍用发行根 `ph_merge_update.py`，由 **ph-init 会话**读发行根 `assets/scaffold/.agents/skills/ph-merge-update/SKILL.md` 执行。禁止重跑 `init --apply`，禁止 `init --adopt-plan`。
- 按下列迁移项合并提问口径、流程旁的问句模板，以及相关 Skill / eval 的用户可见说明。保留项目对这些文件的本地定制，不整树强盖，不重写业务正文。

### 未安装 PH 的存量仓库

无需本项：首次接入直接用 1.1.6 的提问口径，不走 merge-update。

### `plain-user-questions`

- 合并 `docs/约束规范/工程规范/对用户提问.md` 与工程规范 README、canonical 导航里的索引。
- 按段落合并 `意图与访谈.md`、`初始化与文档补全.md`、`Git与并行开发.md` 中“对用户怎么问”的句子；四类整合内部标题、覆盖报告字段、adopt / inspect / finalize 命令保持原样。
- 合并根 `SKILL.md` 与 `ph-merge-update`、`ph-intent-new` / `impl` / `drop`、`ph-worktree-enter` / `exit`、`ph-memory-capture` / `ask` 的用户问句；evals 只补“向用户提问用日常用语、不把内部字段当问句”。
- 不同步业务 Wiki、意图正文、访谈原话或项目已填约束。不因本项重跑文档补全。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、业务事实、用例源文件，以及 subagent 已合并的 Wiki / 规范产物。
- 十 Skill 契约、Schema 1.1.1 与原 adapter mode；脚本命令、`ph.json` 字段、覆盖报告五态、四类整合内部标题。
- 已填写的提问例外或项目自己的对用户说明；不得用新模板覆盖这些定制。
- 未完成升级的 `.agents/updates/<ver>/` 进度：已落地项不重做。

## conflict

- 新问法模板与项目明确约定的对外话术相反：停止受影响项，标 `blocked`，记录原约定与需裁决事项；不得擅自改项目已写的用户说明。
- 仓内版本新于本包：内核阻断，不降级、不改磁盘。
- 路径不安全、根 `AGENTS.md` 无 canonical、受跟踪 worktree 等继续 fail-closed。备份按项目授权保留，不使用 rm。

## verify

1. 已安装项目：`plain-user-questions` 有真实 evidence，必需项无 pending / blocked；已填字段与无关业务正文仍保留；用本版发行根执行 `ph_merge_update.py verify`、`finalize`（经授权 `--apply`），再按原 mode 常规 `check`。
2. 抽查接入冲突、升级确认、废弃“先不做”、工作区清理：问句能让没读过 PH 内部文档的人直接选；问句和选项里不出现禁用内部词；报告和代理笔记仍可用旧字段名。
3. verify / finalize 只检查结构与状态，不证明语义正确；重复执行不重复插入，失败保持 in_progress，未完成迁移项不得推进 `template_version`。
