# 1.1.7 → 1.1.8

## why

此前 PH 的发行版本和配置格式版本分别维护，用户需要理解两个编号。从 1.1.8 起只保留 PH 版本，删除独立的 `schema_version` 字段。配置校验文件继续随发行包提供，格式变化在对应 PH 版本的迁移说明中记录。

取消该键有一个必须直说的后果：旧版（1.1.7 及更早）的 `ph_release.py prepare` 校验发行元数据必须含 `schema_version`，而 1.1.8 发行包不再携带该键，因此**旧入口的 prepare 必然拒绝新包**（报 `illegal release.json: missing schema_version` 一类错误）。这是预期行为，不是可自动恢复的故障；本批用一次性入口切换处理，见 `to`。

## from

- PH 1.1.7、Schema 1.1.1、十个必需 Skill；用户入口只有 `ph-init`，已装旧版由同一会话按发行根 merge-update 步骤升级。
- `release.json.version` 为 `1.1.7`，`schema_version` 为 `1.1.1`。
- 项目 `.agents/ph.json` 含 `schema_version` 与 `template_version`；`template_version` 表示项目已完成适配的版本。
- `.agents/ph.schema.json` 的 `$id` 为 `urn:ph:schema:project-harness:1.1.1`，`required`/`properties` 含 `schema_version` 字段。
- 旧入口 prepare 校验 `release.json.schema_version` 必须存在且为 semver。

## to

- PH 1.1.8 为单一版本：`release.json` 只有 `version`，项目 `.agents/ph.json` 只有 `template_version`，均不再有 `schema_version` 键。
- `.agents/ph.schema.json` 的 `$id` 固定为不带版本的 `urn:ph:schema:project-harness`，不另升编号，也不再有 `schema_version` 字段。结构契约今后随 PH 版本一起变化，并在该版迁移说明中写清。
- `template_version` 语义不变：仍是项目**已完成升级**的 PH 版本，不是下载到的更新包版本。`format_version` 等内部格式标识不动。
- **一次性入口切换（v1.1.8 稳定标签发布后适用）**：已装项目的会话发现旧入口 prepare 拒绝新包时，不得重试、不得回退、不得假称自动恢复；应把官方稳定标签 v1.1.8 clone 到一个**新的仓外安全目录**（如 `mktemp -d`），不覆盖用户级入口与目标项目，不用 `main` 或本地开发树冒充发行；在该新目录运行 `python3 <新目录>/scripts/ph_release.py prepare --version 1.1.8`，读取返回 `root` 的 `SKILL.md` 按其步骤继续。标签未发布前不得实际执行该下载。
- 升级仍由 ph-init 会话按发行根 merge-update 步骤完成：不对已装项目 `init --apply` / `--adopt-plan`；用户确认后用新根 `inspect` → 语义合并 → `verify` → `finalize`。
- 合并阶段先更新无版本 `$id` 的配置校验文件和自包含运行脚本，verify 会检查它们已符合目标发行包。升级候选只在 finalize 的候选检查通过后才写 `template_version=1.1.8` 并移除旧 `schema_version` 字段；随后常规检查通过才标记完成。失败保持 `in_progress`，不提前删字段。

取得新版工具的命令示例（确认新目录位于目标仓库外，替换目标项目路径后使用）：

```bash
TOOLS_DIR="$(mktemp -d /tmp/ph-init-tools.XXXXXX)"
git clone --depth 1 --branch v1.1.8 --single-branch https://github.com/chenweixuanJokes/ph-init.git "$TOOLS_DIR"
python3 "$TOOLS_DIR/scripts/ph_release.py" prepare --version 1.1.8 --repo /path/to/project
```

clone 只用于取得新版下载工具；安装和升级使用随后 prepare 返回的 `root`。保留新目录供本轮升级使用，不覆盖用户级旧入口。升级后项目内的 ph-init 已更新；如果客户端仍优先加载用户级旧副本，需调整其技能入口，不能声称旧副本也已更新。

## affected

分两类目标处理；已安装项目的状态写入 `.agents/updates/1.1.8/state.json`，证据记录到 `report.md`。跨版本升级读取整条迁移链，进度目录用最终目标版本。

### 已安装 PH 的存量项目（1.1.7 及更早）

- 会话从旧用户级入口触发升级时，先按 `to` 完成一次性入口切换，再用新发行根执行 merge-update。禁止重跑 `init --apply`，禁止 `init --adopt-plan`。
- 按下列迁移项合并发行有效内容，保留项目对 Skill / 文档的本地定制，不整树强盖，不重写业务正文。

### 未安装 PH 的存量仓库

项目尚无旧清单，无需删除字段。若调用的用户级工具仍是旧版，也须先完成上述入口切换，再用新版工具准备 1.1.8 并首次安装。

### `single-ph-version`

- 合并根 `SKILL.md` 与 `ph-merge-update` 中“本批版本 1.1.8、单一版本、无 `schema_version`、schema `$id` 固定无版本”的口径，以及一次性入口切换的说明。
- 项目 `.agents/ph.json`：仅在 finalize 通过后删除 `schema_version` 键并写 `template_version=1.1.8`；中途保持原值，不因开始升级就删字段。
- `.agents/ph.schema.json` 更新为无版本 `$id` 且不含 `schema_version` 字段的版本。
- 项目内 ph-init runtime（`release.json`、`scripts/`、`migrations/`、evals 等）更新为 1.1.8 发行内容，保留该副本上的项目定制。
- 跨版本升级时，旧 `schema-contract` 项涉及的中间格式以本项最终格式为准，不再写回 `schema_version` 或带版本的 `$id`。旧迁移记录保留原样。
- evals 只补：旧入口 prepare 拒绝新包时按一次性入口切换处理；finalize 后清单不再含 `schema_version` 不是错误。
- 不同步业务 Wiki、意图正文、访谈原话或项目已填约束。不因本项重跑文档补全。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、业务事实、用例源文件，以及 subagent 已合并的 Wiki / 规范产物。
- 十 Skill 契约与原 adapter mode；覆盖报告五态、四类整合内部标题等脚本安装字段。
- 旧业务正文、既有模式、进行中条目与未完成升级的 `.agents/updates/<ver>/` 进度：已落地项不重做。
- 官方下载地址、匿名 git 下载、失败则关的版本 / 网络策略；1.1.7 的加星 / 建副本附加行为不变。

## conflict

- 项目内工具或规则显式依赖 `ph.json` 的 `schema_version` 字段或带版本 schema `$id`：停止受影响项，标 `blocked`，记录依赖位置请用户决定；不得擅自改项目工具，也不得为兼容保留双版本假象。
- 项目显式约定“不得更换 ph-init 入口目录”：一次性入口切换属发行必需动作，仍先向用户说明并获确认后再执行；未确认前只报告，不 clone、不写盘。
- 仓内版本新于本包：内核阻断，不降级、不改磁盘。
- 路径不安全、根 `AGENTS.md` 无 canonical、受跟踪 worktree 等继续 fail-closed。备份按项目授权保留，不使用 rm。

## verify

1. 已安装项目：`single-ph-version` 有真实 evidence，必需项无 pending / blocked；已填字段与无关业务正文仍保留；用本版发行根执行 `ph_merge_update.py verify`、`finalize`（经授权 `--apply`），再按原 mode 常规 `check`。
2. finalize 后：项目 `.agents/ph.json` 无 `schema_version` 键且 `template_version` 为 `1.1.8`；`.agents/ph.schema.json` 的 `$id` 为 `urn:ph:schema:project-harness` 且不含 `schema_version` 字段。
3. 一次性入口切换只发生在仓外新目录：用户级旧入口与目标项目未被该 clone 覆盖；prepare 输出的 `root` 指向新目录下载的 1.1.8 发行根，`version`/`tag`/`commit` 与 v1.1.8 一致。
4. verify / finalize 只检查结构与状态，不证明语义正确；重复执行不重复插入，失败保持 in_progress，未完成迁移项不得推进 `template_version`。
