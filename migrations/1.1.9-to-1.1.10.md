# 1.1.9 → 1.1.10

## why

文档同步此前只是文档流程：`docs/约束规范/工程规范/文档治理.md` §6 写明“这是文档流程，不是 Skill”，初始化与文档补全的 D58 条目也写“无独立 Skill”。用户要求“同步文档”“检查 README 是否过期”时没有可点名的技能入口，容易误入初始化补全（一次性流程）或 `ph-init` `check` / `sync`（只管适配层），实际核验修复流程反而无人接手。

本批把该流程落成随 scaffold 下发的第十一个必需 Skill `ph-docs-sync`：对照当前代码、配置、锁文件、CI 与近期提交核验 README、docs 配置说明、使用示例与 Wiki 现行叙述，只修可直接证实的不一致；行为与文档治理 §6 的规则一致，§6 仍是规则源。

## from

- PH 1.1.9，十个必需 Skill，项目清单只有 `template_version`；三工具适配拓扑（canonical `.agents/` + 根 `AGENTS.md`；Claude Code 用 `CLAUDE.md` 与 `.claude/skills/`；Codex、OpenCode 原生读取）。
- 文档治理 §6 标题“Wiki 同步检查与修复”，正文写明“这是**文档流程**，不是 Skill。不存在 `ph-wiki-sync` / 定时巡检任务”。
- 初始化与文档补全 §1 写“不改 PH 十个固定 Skill，不声称存在 Wiki 同步 / Wiki 纠正 / Wiki 问答 / 记忆纠正的专属 Skill”；§5.6 的 D58 行写“**文档流程**，无独立 Skill”。
- `.agents/AGENTS.md` 的 PH Skills 表为十名，无同步类条目。

## to

- PH 1.1.10，十一个必需 Skill：新增 `ph-docs-sync`（`.agents/skills/ph-docs-sync/`，含行为样例 `evals/evals.json`）。`release.json.required_skills` 与 manifest `skills.required_names` 均为十一项，`template_version=1.1.10` 仅在 finalize 验收通过后写入。
- 文档治理 §6 改名“文档同步检查与修复”，写明由 `ph-docs-sync` 执行、本文仍是规则源；仍不存在 `ph-wiki-sync` 与定时巡检任务，检查默认只读。§7 改为“记忆纠正没有专属 Skill；文档同步检查与修复走 `ph-docs-sync`”。
- 初始化与文档补全改为“不改 PH 十一个固定 Skill”，D58 行指向 `ph-docs-sync`；补全时不调用该 Skill，初始化补全与日常同步互不替代。
- `.agents/AGENTS.md` PH Skills 表为十一名并新增 `ph-docs-sync` 行；根 `SKILL.md`、`README.md`、`ph-merge-update` Skill 同步更新数量、分流与迁移项说明。
- **升级只安装该 Skill 并合并规则索引，不自动同步任何业务文档**：README / docs / Wiki 的核验与修复由用户另行发起 `ph-docs-sync`，升级过程不代替执行。
- adapter mode、项目定制、业务正文与未完成升级记录全部保留。

- 项目定制与已填事实：`.agents/AGENTS.md`、文档治理、初始化与文档补全中的项目段落按语义合并保留；manifest 自定义字段、adapter mode、验证命令不变。
- 同名自定义 Skill：旧版不携带 `ph-docs-sync`，升级前已存在的 `.agents/skills/ph-docs-sync/` 视为项目内容，原件保留待用户决定。
- 历史意图、访谈纪要、Changelog、已发布迁移说明与 `.agents/archived/`、`memory/archive/` 原件不改写。
- 未完成升级记录（`.agents/updates/`）与 state 中已完成项不重做。

## conflict

- `.agents/skills/ph-docs-sync/` 已有项目自定义内容（旧版不携带该 Skill，同名即项目内容）：本项 `blocked`，保留原件并请用户决定改名保留或替换为官方版。形态规整的同名目录（真实目录 + 常规 `SKILL.md`）由 `inspect` 列入冲突清单；无 `SKILL.md`、含软链 / 硬链等异常形态会先被结构校验直接拒绝——两种路径都 fail-closed，不得覆盖、不得凭前缀猜测放行。
- 项目规则明确禁止自动修正文档、禁止文档同步或禁止新增 `ph-*` Skill：本项 `blocked`，停止受影响写入并请用户裁决，不削弱项目规则。
- 代码 / 配置与约束规范矛盾：不在本项内改规范迁就代码，记录冲突交用户（规范冲突不降级规范）。
- 其余通用门禁（根 AGENTS 在而 canonical 不在、仓外软链、嵌套 symlink/junction、受跟踪 `.worktrees/`）保持 fail-closed。
