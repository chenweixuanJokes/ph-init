# 1.1.3 → 1.1.4

## why

存量仓库接入 PH 不能先落模板再盖旧正文：1.1.3 的 init 只复制脚手架，canonical 与既有正文不一致一律冲突，成熟项目带着既有 `AGENTS.md` 正文与旧文档目录时无法受控接入。本批把存量接入改成“已有内容优先”：会话在仓外生成 `sources` 快照与合并候选，内核校验哈希后经 `init --adopt-plan` 落盘，初始化补全须产出可核对的覆盖报告。已安装项目升级仍走 `ph-merge-update`，不重跑 init。

## from

- PH 1.1.3、Schema 1.1.1、十个必需 Skill；init 无 `--adopt-plan`，canonical 与脚手架不一致一律冲突。
- 存量未接入仓库实际只能“先装模板、会话再改”；旧 `docs/` 内容靠“保留待会话审阅”兜底，没有合并基准快照。
- `--mode` 缺省在 init 恒为 `portable`，check / sync 才从适配层推断；已安装同版重跑 init 会因定制 canonical 冲突。
- 指引已有四类状态与条目矩阵，但没有七类证据盘点、旧目录处理与 `.agents/init-report.md` 覆盖约定。

## to

- PH 1.1.4，Schema 保持 1.1.1、十个 Skill、adapter mode 不变；`init` 新增 `--adopt-plan <plan.json>`。
- plan 契约：`version` 固定 `1`；`repo` 是目标仓绝对路径；`release_version` 等于本发行包版本；`sources` 是 `{仓内相对路径: 正文 SHA256，缺失为 null}` 快照，必含 `.agents/AGENTS.md`、`AGENTS.md`、`CLAUDE.md` 三个入口及 `files` 全部目标；`files` 候选只允许 canonical `.agents/AGENTS.md`（必需）与 `docs/**`。plan 在目标仓外生成；内核核对 `sources` 哈希与目标实态一致才写入。
- 仅当目标尚无 `.agents/ph.json` 才允许 adopt；已安装仓库执行 adopt 被拒绝并指向 `ph-merge-update`。
- 未带 adopt 的 init：已安装同版仓库重跑保留定制 canonical（不再冲突）；未安装仓库 canonical 不一致仍阻断并提示走 adopt 流程。`--mode` 缺省先读 `.agents/ph.json` 声明，再从适配层推断，仍推断不出才用 `portable`；init / check / sync 一致。
- 指引升级：七类证据盘点（模块、代码、配置、真实依赖、测试、CI、旧约束）、dry-run 四类整合（直接落地 / 复用引用 / 冲突待裁决 / 不适用与保留）、旧文档目录按内容归并进三域（不留旧目录、空壳或软链；摘要 + 深链指向归并后的正文）、写前把原文备份到 `.agents/archived/<日期>-pre-init/`（仓内可恢复原件，不再要求仓外原文备份）、`.agents/init-report.md` 覆盖矩阵全部独立 id。

## affected

分两类目标处理；已安装项目的状态写入 `.agents/updates/1.1.4/state.json`，证据记录到 `report.md`。跨版本升级读取整条迁移链，进度目录用最终目标版本。

### 已安装 PH 的存量项目（1.1.3 及更早）

- 升级唯一入口是 `ph-merge-update`：prepare 固定本版发行根，inspect 只读，Agent 按本说明合并，verify / finalize 验收。禁止重跑 `init --apply`，禁止 `init --adopt-plan`（内核会拒绝已安装目标）。
- 按下列迁移项合并项目已装 `.agents/skills/ph-init/`（`SKILL.md`、`scripts/ph_init.py`、release 元数据、迁移材料、evals、内嵌 scaffold）与 `ph-merge-update` 的本次边界，保留项目对该 Skill 的本地定制，不整树强盖。

### 未安装 PH 的存量仓库

无需迁移记录：首次接入直接用 1.1.4 流程——prepare → 七类证据盘点 → dry-run 整合报告 → 仓外生成合并候选 → `init --adopt-plan`（先 dry-run 再 `--apply`）→ 已装内核 `check` → 逐项补全并维护 init-report。不要先跑无 adopt 的 `init --apply` 落模板再盖旧正文。

### `adopt-plan-init`

- 合并 `scripts/ph_init.py` 与根 `SKILL.md` 的 adopt 契约：仓外 plan、`sources` 哈希护栏（防错仓、错时点与中途变更，不证明候选语义正确，语义由会话 Agent 负责）、候选写入集限定 canonical 与 `docs/**`、已装目标拒绝 adopt、同版重跑保留定制 canonical、mode 缺省推断顺序。
- 同步合并根 `evals/evals.json` 新场景（11–14：存量规则接入、旧目录归并、纯代码仓反推、旧规范与实态冲突；并覆盖附件随迁、同主题合成单一正文、真实计划无审批证据）。

### `adopt-existing-content`

- 按发行包 `docs/约束规范/工程规范/初始化与文档补全.md` 逐段合并：1.1 存量内容与旧目录、3.3 dry-run 四类整合、3.4 仓外合并候选与安装、第 5 节逐条执行规则（每条结论须有仓内证据，已覆盖条目记 `复用`）。已拆专文或已改写的项目在现有落点合并，保留已填写命令、例外与技术栈，不复制第二套。
- 合并 `.agents/AGENTS.md` 导航、`docs/约束规范/工程规范/文档治理.md` 与工程规范 README 的对应条目：旧文档目录（如 `docs/specs/`、`docs/domains/`、`docs/plans/`）按内容归并进三域，不留旧目录、空壳或软链；PH 固定入口（`docs/README.md` 与 canonical 导航）摘要 + 深链指向归并后的正文，被引用旧规范保持效力。补齐 `.agents/archived/README.md`：将被覆盖或移走的原文先原样备份到仓内带日期快照，不再要求仓外原文备份。内核 adopt 仍只写 canonical 与 `docs/**`，不自动搬移或删除。

### `init-report-coverage`

- 合并 `.agents/init-report.md` 覆盖报告约定（指引第 6 节）：矩阵每个独立 id 至少一行，列为 `id` / `落点` / `仓内证据` / `结果` / `说明`，结果枚举 `已核验` `复用` `不适用` `待核实` `冲突`；PH 通用流程条目写采用声明，不为它们编造项目执行记录。
- `init-report` 是实现记录：不进 `docs/` 三域、不替代规范 / Wiki 正文 / 意图记录，也不因它自动生成意图或记忆。

## preserve

- 项目真实技术栈、已填约束、规范例外、命令、CI 通道、业务事实、用例源文件，以及 subagent 已合并的 Wiki / 规范产物。
- 接入前旧文档的内容、历史记录、附件与 README 独有正文必须保留：按旧路径 → 新落点归并进三域，不推定废止；被引用旧规范保持效力，除非用户明确废止。不把旧目录长期并存当作完成。
- 根 `AGENTS.md` 等既有正文接入时以复用 / 引用登记，不复制第二套，不重写已有证据的正确内容；摘要深链指向归并后的正文。内核 adopt 不自动搬移或删除；会话在本轮授权内写映射、把原文备份到 `.agents/archived/<日期>-pre-init/`、修活动引用与索引后再移出活树旧文件。仓内快照即是可恢复原件，不再要求仓外原文备份。
- Wiki owner / 核验历史、ADR 决策依据、访谈原话、意图编号、记忆原件及其效力；十 Skill 契约、Schema 1.1.1 与原 adapter mode。
- 已安装同版项目重跑 init 时已定制的 canonical 原文。

## conflict

- 旧正文之间、旧正文与代码 / 锁文件 / CI 矛盾：事实以当前实态为准记 `已核验`，规范冲突记 `冲突` 并留双方证据，交用户裁决；不覆盖、不悄悄改旧文。
- adopt 候选 `sources` 哈希与目标实态不一致：内核阻断该次安装；会话重新盘点生成新候选，不手改哈希凑通过。哈希护栏只防错仓、错时点与中途变更，不证明候选内容正确。
- PH 新指引与项目明确约定冲突、同名文档用途不同且无法兼容：停止受影响项，标 `blocked`，记录原内容与需裁决事项。
- 路径不安全、根 `AGENTS.md` 无 canonical、受跟踪 worktree 等继续 fail-closed；不得挪走阻断文件强装。备份按项目授权保留，不使用 rm。

## verify

1. 已安装项目：三个迁移项都有真实 evidence，必需项无 pending / blocked；已填字段、旧文档内容与无关业务正文仍保留；用本版发行根执行 `ph_merge_update.py verify`、`finalize`（经授权 `--apply`），再按原 mode 常规 `check`。
2. 未安装仓库只在隔离临时 Git 仓验证 1.1.4 接入流程（adopt 先 dry-run 再 apply、装后 `check`、init-report 覆盖全部独立 id），绝不在已装目标上验证，不重装目标。
3. 已装 ph-init 包携带新 `scripts/ph_init.py` 与指引：`--adopt-plan` 对已装目标报错并指向 merge-update、同版重跑保留定制 canonical、mode 缺省先读 `.agents/ph.json` 声明。
4. verify / finalize 只检查结构与状态，不证明语义正确；重复执行不重复插入，失败保持 in_progress，未完成迁移项不得推进 `template_version`。
