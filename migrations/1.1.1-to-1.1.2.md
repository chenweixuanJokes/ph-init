# 1.1.1 → 1.1.2

`v1.1.1` 已发布。本批取消两个旧意图状态：`已完成/`（交付语义改为“留在实施、「记录」注明结果”）与旧 `进行中/` 兼容目录（存量条目按是否已启动归入待办或实施）。其余 Skill、目录结构与 Schema 契约不变。

## why

1. 生命周期各转换都有明确入口——`new` 新建入待办、`impl` 迁入实施、`drop` 移入已废弃——唯独“实施→已完成”没有任何 Skill 负责，只能事后人工移动，实践中从未发生，条目长期滞留。
2. 取消该状态后目录即完整表达生命周期：交付结果写在意图「记录」，不需要也不可能再有迁移动作。
3. 旧 `进行中/` 是 1.1.1 之前的唯一活跃状态，1.1.1 只做按需兼容；保留它会与新待办/实施语义长期并存，第三个“活跃”目录没有独立含义，应按证据收编进新结构。

## from

- 已发布 `v1.1.1`：`docs/意图/` 含 `待办/` `实施/` `访谈纪要/` `已完成/` `已废弃/`，部分项目另留旧 `进行中/`（空模板或存量业务条目）；治理与模板规定“完成后移入已完成”。

## to

- `docs/意图/` 不再包含 `已完成/` 目录，导航、目录表与模板不再引用它。
- `docs/意图/` 不再包含旧 `进行中/` 目录：存量条目按证据迁入待办或实施，空模板目录移除，三个意图 Skill 与规范不再含进行中兼容分支。
- 交付的意图留在 `实施/{新特性,问题记录}/`，在「记录」追加日期与验收证据；不因实现进度自动记录交付。
- 三个意图 Skill 边界同步：已交付意图位于实施，重复 `impl` 幂等继续；`new` 不因补充默默重开已交付条目；`drop` 面向已交付条目时先确认是下线或撤回已交付能力。
- `template_version` → `1.1.2`；`schema_version` 保持 `1.1.1`。

## affected

按 `items` 拆开，只改该项要求的文件。

- 规范与模板：`文档治理.md` 目录表与移动规则、`意图与访谈.md` 完成语义、`docs/意图/_模板.md` 与 `实施/{新特性,问题记录}/README.md` 的移动提示。

- 目录：仅含空模板的 `docs/意图/已完成/` 备份后移除。
- 存量条目：真实 `已完成/` 条目逐条迁入对应 `实施/{新特性,问题记录}/`——`status_dir` 改为实施路径，正文有效链接按新目录重算（如 `../访谈纪要/` → `../../访谈纪要/`），更新沿途 README，并在「记录」追加一条迁移动机；编号、历史正文、纪要位置不变。

### intent-legacy-inprogress

- 存量条目逐条按证据归类：意图「记录」或「计划交接」显示已启动推进（计划获批、实施完成、交付里程碑）→ 对应 `实施/{新特性,问题记录}/`；仅有录入/澄清证据 → `待办/{新特性,问题记录}/`。同深度移动，`status_dir` 更新，当前有效相对链接逐个重算核实，沿途 README 同步，意图「记录」追加一条迁移依据；证据不足以判断是否已启动时该项 `blocked`，请用户裁决，不猜。
