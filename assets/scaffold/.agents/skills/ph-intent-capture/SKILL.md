# ph-intent-capture

把用户目标澄清成可规划的意图，保留问答证据。使用访谈机制不意味着必须凑出问题；已明确的内容直接复用。此 Skill 不自动规划或实现。

## 入口与规则

1. 从当前目录向上定位同时存在 `.agents/ph.json` 和 `.agents/AGENTS.md` 的仓库根。找不到则说明当前不是 PH 仓库并停止，不自行初始化。
2. 读取当前项目约束，以及仓库根下 `docs/约束规范/工程规范/意图与访谈.md`、`docs/意图/_模板.md`、`docs/意图/访谈纪要/_模板.md`。使用仓库自身规则，不依赖用户主目录的 `interview` Skill。
3. 写入或移动只限当前意图、纪要、必要索引和相关链接。遵守宿主模式权限；只读时不落盘，返回草稿和待归档说明，不能报告录入已完成。
4. 目标必须在本仓库意图域内，写前读文件并检查路径，不跟随软链/junction 重定向到其他位置。待写内容先去密，不记录凭证值或个人敏感信息。

## 工作流

### 1. 找到要记录的目标

- 提取用户希望解决的问题和预期结果，先不替用户指定技术实现。
- 检索当前对话、已有意图、历史纪要、相关代码和资料。已有内容能回答的问题直接引用，不重复问技术栈、目录或现有能力。
- 按编号或路径指定的意图先读取原件；不要只看标题就另建。疑似重复时先比较，确有“补充原意图还是独立新意图”的分歧才问。
- 已完成或已废弃意图不能默默重开；说明当前状态，只在用户明确选择新建后另立意图并关联历史。本 Skill 不代替恢复或状态迁移流程。

### 2. 建立可持续记录的草稿

- 新意图使用稳定 `INT-YYYYMMDD-短主题` 编号和 `<intent_id>.md` 文件名，查重后放入 `进行中/新特性/`（feature）或 `进行中/问题记录/`（issue）。日期取实际当地日历日，不编造用户、负责人或背景。
- 按模板填已有事实，未知项明确留待澄清，`clarification_status: pending`；保持 `status_dir` 与目录相符。当前类型尚不明确时先记录纪要中的编号和待建立链接，不硬猜分类。
- 在 `docs/意图/访谈纪要/` 建立本次 purpose 为 `capture` 的纪要；意图的 `interviews` 用仓库根相对路径引用，纪要用同一 `intent_id` 关联。
- **首次提问前的保存检查**：普通可写模式下，先通过实际文件工具建立本次 `ongoing` 纪要、已有信息的 `pending` 意图草稿及相互引用和索引，确认操作成功后才停下来向用户提第一问。不能只输出“稍后记录”的承诺。若意图类型尚未确定，至少保存纪要和已分配编号，标明草稿关联待建立；不为填写草稿编造答案。若写入失败，说明未保存并停止录入流程，不把口头问题当成已留痕。
- 同一会话的工具重试先检查已写条目，不重复创建或追加；新会话续访使用新纪要并关联旧纪要，不改历史答案。
- 维护已有旧版意图时复用 `related` 中的旧纪要，按需补新字段，不全库迁移、不重分配编号。

### 3. 只问影响目标的缺口

每轮遵守共用规则：**先调研 → 说明为什么问 → 一个问题与推荐选项 → 等用户回答 → 保存本轮**。

- 问之前确认答案不能从现有证据查清，且确实会改变目标、范围、验收或关键约束。
- 使用结构化问答工具时一次提交一个问题；无工具时以普通文本给出同等选项并停止等待。推荐项置首，附理由，允许自由回答。
- 不把多个独立决策塞入一轮，不把选项默认值、沉默或推断当成用户选择。
- 每轮得到回答后及时追加实际问题、原因、证据、选项及推荐理由、回答、确认结论和未决问题，更新意图及索引，再问下一轮。
- 用户中断时保留已答内容，将纪要标为 `paused`；仍有关键目标缺口则保持 `pending`，不靠已有一份纪要就判定充分。

### 4. 收敛成意图

当以下信息已经明确且彼此一致时完成澄清：对象与场景、当前问题、预期结果、范围与非目标、关键约束、可验证验收标准；不存在会改变这些结论的关键未决问题。

- 无真实缺口可以零新增问题，纪要写明本次复用的答案和来源，不虚构轮次。
- 整理模板中的各节，将 `clarification_status` 改为 `clear`，纪要标为 `complete`。保留历史与实际问答，不用总结替换原记录。
- 简短回述目标与关键决定；有实质分歧才追问，不固定追加无意义的确认问题。
- 检查本次纪要和意图双向可追溯、编号不重复、路径/状态一致、README 覆盖新增文件、当前有效链接可解析。frontmatter 路径相对仓库根，Markdown 链接相对所在文档，不混用。
- 不照抄模板原位置的相对链接。例如 `进行中/新特性/<id>.md` 引用纪要应为 `../../访谈纪要/<iv>.md`；引用工程规范应为 `../../../约束规范/工程规范/意图与访谈.md`。逐个从实际目标文件父目录解析并确认存在；断链未修复前不报告录入完成。零新增问题的 `clear` 意图同样必须引用记录复用依据的真实纪要，不能只写“已访谈”。

## 交付

返回意图和纪要的实际路径、澄清程度、验收要点与尚未解决的问题。区分“草稿已保存”“目标已澄清”“只读模式待归档”，不把任何一种说成已规划、已实现或已完成业务意图。停在录入边界，不自行调用规划或执行流程。
