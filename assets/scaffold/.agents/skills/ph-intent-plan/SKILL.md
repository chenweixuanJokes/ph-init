# ph-intent-plan

准备充分后交接，而不是在普通模式先写一份完整计划、切换后再写一遍。允许在普通模式启动；正式实施计划交给宿主原生计划模式。本 Skill 不自动实施。

## 入口与权限

1. 向上定位同时存在 `.agents/ph.json` 和 `.agents/AGENTS.md` 的 PH 仓库。缺失时停止，不自动安装 PH。
2. 读取当前项目约束、仓库根下 `docs/约束规范/工程规范/意图与访谈.md`、意图及纪要模板。定位唯一目标意图，先检索再询问真正的目标歧义。
3. 遵守宿主当前模式和写权限。已经在计划模式时直接进入下文“原生计划阶段”，不退出再重进；意图虽未充分澄清，也不能借补访越过只读限制。
4. 模式依据只能来自当前宿主明确的系统信号或原生工具返回。存在计划文件、用户要求规划、自设环境变量或 `--plan-mode` 参数都不是证据。无法确认权限时停止受限写入，不能默认可写。
5. 读写范围为当前意图、相关纪要、必要索引与引用；无业务代码写入权限。检查仓库内路径，拒绝软链/junction 重定向；所有持久化内容先去密。

## 普通模式：准备交接

### 1. 研究意图与当前事实

- 读取意图、`interviews` 和旧 `related` 中的相关纪要、项目约束及受影响代码、配置、测试。检查旧结论是否已因代码或需求变化失效。
- 不以 `clarification_status: clear` 或“已经访谈过”代替实际核对；也不因模板字段缺失就否定历史中已经明确的答案。
- 已废弃或已完成意图不直接按新需求规划；说明状态和范围冲突，不擅自重开、迁移或自动另建意图。
- 区分用户决策缺口和可在计划模式继续研究的技术问题。不要求用户替 Agent 做代码调研。

### 2. 必要时补访并保存

- 目标、范围或验收仍不明确，或当前证据产生新的关键取舍时，按共用访谈规则补访。
- 每轮先查，说明提问原因，一次一个决策，推荐选项置首并给理由，允许自由回答；得到实际回答后及时保存，再决定下一问。
- 需要补访时创建 purpose 为 `plan` 的新纪要，由意图 `interviews` 引用；保留旧纪要原文，新结论注明取代或修正了什么。
- 本次没有补访则直接引用已有证据，不为凑数量创建虚假问答。若实际执行了澄清性讨论，必须记录过程，不能只留下结论。
- 关键用户决定仍缺失时停在澄清阶段，记录待继续问题，不切换后假装缺口已解决。用户中断时保存已回答内容及 `paused` 状态。

### 3. 写规划输入，不写完整计划

在意图的“计划交接”节整理：

- 意图编号及当前路径、目标、范围和非目标；
- 关键约束与验收标准；
- 已明确的用户决定与纪要引用；
- 相关代码、配置、测试的路径和已核实事实；
- 风险、待研究的技术问题及证据限制。

这里不提前制定最终架构、逐步实现任务或完整实施计划。更新日期、必要索引和链接，核实写入成功。交接材料是当前快照，历史问答仍保留在纪要中。

### 4. 驱动会话切换

- 查看宿主实际暴露的原生计划模式能力；例如本会话确有 `EnterPlanMode` 时才使用，不能假定所有 Agent 有同名工具或虚构命令。
- 调用原生切换能力，需要用户批准则遵守宿主流程，等待并检查实际结果。
- 宿主明确确认进入计划模式后，继续下节的正式规划；只有“请求已发出”不代表切换成功。
- **没有切换能力**：给出已保存的意图/纪要/交接位置，说明“准备已完成，请手动将本会话切到计划模式后继续”，然后停止；不继续输出完整计划。
- **被拒绝、失败或无法确认**：如实说明状态并停止。不要反复重试被拒绝的调用，不通过另起会话或自称模式切换绕过限制。
- 无需改名或移动意图来表达切换成功，切换也不代表计划已获批。

## 原生计划阶段

1. 确认宿主当前处于计划模式，读取目标意图和交接材料。已在该模式调用本 Skill 时，可直接做同样的只读调研，无需重复生成交接文件。
2. 有新缺口再按同样的一问一答机制补访。没有项目写权限时将实际问答保留在会话或宿主明确允许的计划产物，列为“待归档、未写入项目”，保留意图编号及引用目标；不得改 docs 或虚报纪要已保存。
3. 正式研究可复用实现和影响范围，制定包含步骤、修改位置、测试与完成标准、风险、必要迁移/兼容安排的实施计划。目标和验收不明确时继续澄清，不用技术方案掩盖需求缺口。
4. 按宿主原生方式交付计划并请求审批，遵守该工具的实际语义。请求规划不意味着计划获批，也不意味着已授权业务实现。
5. 返回实际计划产物位置或宿主提供的计划内容，不编造文件路径。待归档纪要及引用作为明确交付项保留；不为了保存这些内容自行退出只读模式，不自动写入厂商未授权的路径。

## 完成状态

- **待澄清**：关键用户决定缺失，准备未完成。
- **待手动切换**：交接准备已保存，但无工具或切换失败；正式计划尚未制定。
- **计划待审批**：真实计划模式内已交付实施计划，仍不代表获批或实现。

分别报告真实状态及已保存/未保存的内容；不把“整理了交接材料”叫作已完成实施计划，不执行代码、测试部署、提交或发布来跨过规划边界。
