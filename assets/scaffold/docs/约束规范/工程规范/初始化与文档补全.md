# 初始化与文档补全

Last verified: <填写：YYYY-MM-DD>

> 本文是 PH 接入后、把占位文档补成**本仓库真实约定与现行叙述**的操作指引。它约束怎么盘点、怎么取证、写到哪、何时可写；不替代各域正文，也不授权部署、通知、造记忆或造意图。
>
> `ph-init check` 只证明适配层与目录骨架可用。**check 通过不等于文档补全完成。**

## 1. 目的与边界

补全目标：

- 把通用强制门禁留在约束文，把本仓库真实栈、命令、通道、用例入口填进对应占位符。
- 把现行事实写进 Wiki 与 `.agents/AGENTS.md` 的一句话 / 技术栈，并标出来源与生效状态。
- 不为脑图或清单上的每个叶子预建空文档；同类约定写入已有汇总文，有独立维护者与足够事实时再拆专文并补索引。

明确不做：

- 不改 PH 十个固定 Skill，不声称存在 Wiki 同步 / Wiki 纠正 / Wiki 问答 / 记忆纠正的专属 Skill。
- 不因补全文档自动新建意图、访谈纪要或记忆条目。
- 不从坏代码、过期 Wiki、未核实博客或模型推断倒推强制规则；建议不得自动升级为规范。
- 不覆盖项目已有定制。冲突或范围扩展时停止受影响项，保留已核验成果。
- 不实际上线、不发送通知、不上传本仓库代码 / 内网材料 / 秘密到公网。

版本与合并升级由发行源维护，不在本仓库业务文档里改 PH 版本号。

## 2. 完成标准

一次文档补全交付必须同时满足：

1. 只读盘点已覆盖代码、锁文件、CI、现有约束 / Wiki / AGENTS，并写明缺口。
2. 实际在用的栈已按第 3.2 节留下官方资料记录；离线或查不到的标 `待核实`，不编造版本。
3. 矩阵中适用条目都有落点：已填真实值、标明 `不适用`，或因冲突停止并留下续做说明。
4. Wiki 非模板页的五个字段均为真实值：`owner` / `status` / `last_verified` / `verified_against` / `refresh_trigger`。owner 未知写 `unknown`，不猜人名。
5. 写入的命令若只是从脚本 / README / CI **静态抄出、本轮未执行**，必须标明 `未执行，待核实`。
6. 沿途 README 与相对链接仍指向真实存在的文件；共享 README 由主会话汇总，不出现双写分叉。
7. 失败或中断时：已验收段落保留，未完成项可续做，不因部分成功宣称全部完成。

未完成补全前，不得把占位符、空表或过期叙述当成现行答案。

## 3. 会话流程

严格按顺序。未获本轮写入授权前只读。

### 3.1 只读盘点

先读，不改：

| 类别 | 看什么 | 用来决定 |
| --- | --- | --- |
| 约束与入口 | [AGENTS.md](../../../.agents/AGENTS.md)、本目录各文、前后端 / 测试汇总文 | 已有强制门禁与定制，保留不覆盖 |
| 代码与模块 | 应用入口、包结构、路由 / API、测试目录 | 有无前端 / 后端、真实边界 |
| 依赖锁 | lock / 清单 / 镜像列表，如 `package-lock.json`、`pnpm-lock.yaml`、`yarn.lock`、`go.sum`、`Cargo.lock`、`poetry.lock`、`composer.lock`、Gradle / Maven lock | 实际在用的语言、框架、中间件 |
| CI 与脚本 | `.github/workflows/`、其它 CI、`Makefile`、`package.json` scripts、构建脚本 | 构建、测试、发布入口 |
| 现有文档 | `docs/` 三域、Wiki 五字段、意图目录是否已有正文 | 哪些是定制、哪些仍是模板 |

盘点结论先区分第 4 节四类状态。规范不能从“代码现在就这样写”推导出来；代码只能提供事实候选。

### 3.2 按实际栈查公网官方资料

只查**本仓库锁文件或清单里真实出现**的组件。不预填邻项目的 Kong / Eureka / Apollo / 某前端框架。

每条记录必须能复核：

| 字段 | 要求 |
| --- | --- |
| 组件 | 仓库内名称与锁文件版本 |
| 官方标题 | 页面标题原文 |
| URL | 公网官方或标准文档地址 |
| 版本 | 页面声明的文档 / 产品版本 |
| 访问日期 | 当地日历 `YYYY-MM-DD` |
| 采用理由 | 为何写入本仓库文档（例如锁文件已钉住该主版本） |
| 状态 | `已采用` / `待采纳建议` / `待核实` |

禁止：把业务代码、内网地址、令牌、完整连接串贴到搜索或第三方服务。网络失败或资料对不上锁文件时，条目标 `待核实`，写明缺口，不假装已核验。

公开方法论文档可参考，但有边界：

- [Diátaxis compass](https://diataxis.fr/compass/)：帮助区分教程 / 操作 / 解释 / 参考，**不**把 `docs/` 改成这四类目录。
- [arc42 Architecture Decisions](https://docs.arc42.org/section-9/)：决策要写背景与后果，落点仍是 [架构决策](../架构决策/README.md)。
- [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)：安全控制清单的参考，**不**自动选定 ASVS 等级。
- [Software Engineering at Google, ch.11 Testing](https://abseil.io/resources/swe-book/html/ch11.html)：测试分层思路，**不**自动套用 Google 的覆盖率或测试数量阈值。

目标栈的官方版本与 API 以本次联网结果为准，不把上述四篇的目录或阈值抄进强制门禁。

### 3.3 dry-run

向用户交出写入计划，至少包括：拟改文件、拟填事实摘要、来源、状态、不改哪些定制。此时不写盘。

### 3.4 已授权 apply

用户明确同意本轮写入范围后才改文件。计划外的文件、部署、推送、发通知、建意图 / 记忆，必须再授权。

### 3.5 分阶段与文件归属

有独立收益时按文件归属拆 subagent；同一文件只允许一个写入者。建议阶段：

1. **栈盘点**（只读，主会话或一个检索 agent）：产出组件表、有无前端 / 后端、CI 入口、现有定制清单。
2. **官方资料**（可按组件并行，只读）：回传第 3.2 节记录，不写项目文档。
3. **写入**（apply 之后，按独立文件并行）：
   - Wiki：`项目概述.md`、`功能地图.md`、`开发指南.md`、领域页、架构三页。
   - 各端：`前端规范.md`、`后端规范.md`。
   - 工程与测试：`测试规范.md`、[安全与配置.md](./安全与配置.md)、[构建发布与运维.md](./构建发布与运维.md)、必要时 [Git与并行开发.md](./Git与并行开发.md)。
4. **共享 README / 入口**：由**主会话**统一更新本轮受影响目录及上级 README，包括 [工程规范 README](./README.md)，以及 `.agents/AGENTS.md` 的一句话与技术栈。subagent 只回传所需索引变更，不抢写共享文件。改 canonical 后按原 mode 同步适配层并重新 check。

失败时保留已验收文件，下轮从盘点结论续做，不重写已核验段落。范围扩展或与原有定制冲突：停止**受影响项**，其它无关文件可继续。

## 4. 来源与生效状态

写入任何句子前先定性。四类不得混写在同一条强制句里。

| 状态 | 含义 | 可落点 | 效力 |
| --- | --- | --- | --- |
| 规范 | 本仓库已接受的强制门禁 | `docs/约束规范/` | 必须遵守；与 Wiki / 记忆冲突时以约束为准 |
| 事实 | 对照当前代码、锁文件、CI 或已执行命令核实的现行情况 | Wiki、AGENTS 一句话 / 技术栈、开发指南 | 现行叙述；`refresh_trigger` 点燃后先重验 |
| 外部待采纳建议 | 官方指南或评审意见，仓库尚未决定采用 | 意图、ADR 草稿，或专文中明确标注“建议、未生效” | 非强制；不得当成门禁执行 |
| 待核实 | 来源冲突、资料不可达或待执行验证的部分 | 原落点，必须带 `待核实` 与缺口 | 不得宣称已核验或已通过；已有门禁不因本轮未运行而失效 |

原有定制（已填事实、已接受规则、已有 ADR / 意图正文）默认保留。要用建议替换定制，必须先停下来问用户，不能在补全过程中“顺手规范”。

## 6. Wiki 五字段与命令标注

非 README、非模板 Wiki 页必须是真实字段，不允许用模板空值冒充已核验：

| 字段 | 补全规则 |
| --- | --- |
| `owner` | 由 CODEOWNERS、现有责任声明或用户明确指定确认；提交作者只能提供线索，不等于当前负责人。无法确认则 `unknown` |
| `status` | `draft` / `active` / `deprecated` 必须与正文一致 |
| `last_verified` | 本次对照事实的日期；未核验保持空，并在正文标明 |
| `verified_against` | 提交、标签或路径；没有 Git 信息就写核过的路径列表 |
| `refresh_trigger` | 沿用页内默认或按真实变化收窄，不留空口号 |

命令写法：

```text
<命令>    # 已在本轮执行，通过
<命令>    # 未执行，待核实（抄自 package.json / CI）
```
