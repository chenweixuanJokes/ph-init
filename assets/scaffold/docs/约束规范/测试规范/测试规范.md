## 1. 三层门禁

| 层 | 目的 | 完成标准 |
| --- | --- | --- |
| 单元 | 锁模块行为 | 默认**全量**绿。定向跑单个测试只作开发内循环，不算完成 |
| 冒烟 | 锁关键路径可走通 | 缺陷先用同一冒烟复现，修复后再用同一用例验证。断言失败即失败，不得跳过 |
| 回归 | 锁合入 / 发布 | 全量单元 + 按影响范围分档的冒烟（及仓库声明的 e2e）。任一层失败阻塞 |

功能做完必须达到：相关层单元全绿 + 受影响冒烟通过。新接口 / 新页面 / 新可复用模块没有对应用例，视为开发未完成。改契约必须改用例。

**重构是大改动**：跨文件重命名、签名调整、抽象提取、模块拆分、公共工具迁移、DSL 或数据结构变更，无论看起来多等价，合入共享基线前必须跑回归。

## 2. 影响范围分档（冒烟 / e2e）

- **全局改动或大重构**：跑全部冒烟（及仓库声明的全部 e2e）。
- **其它改动**：只跑推断受影响的剧本，并把推断依据写进测试报告或意图。拿不准按全局处理。

全局的例子：鉴权、HTTP 客户端、路由框架、设计令牌、依赖大版本、构建配置。

## 4. 证据与环境

- 冒烟执行后必须留下证据（日志路径、报告、或用例内“证据记录”）。没有证据的“我跑过了”不算通过。
- 测试所需进程由开发者按 [开发指南](../../项目Wiki/开发指南.md) 自行启动；启动前按该页要求重建产物，避免 stale class / stale bundle。
- 禁止用生产凭证跑本地测试。密钥不入库。
