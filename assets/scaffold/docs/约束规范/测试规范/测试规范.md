## 1. 统一门禁

| 层 | 目的 | 完成标准 |
| --- | --- | --- |
| 单元 | 锁模块行为 | 默认**全量**绿。定向跑单个测试只作开发内循环，不算完成 |
| 接口 | 锁 HTTP / RPC 契约（有后端且仓库声明时） | 用例与契约同步；改契约必须改用例 |
| 端到端 | 锁跨端或跨服务关键路径（仅仓库声明启用时） | 选定剧本全绿；未启用则本层不适用 |
| 冒烟 | 锁关键路径可走通 | 缺陷先用同一冒烟复现，修复后再用同一用例验证。断言失败即失败，不得跳过 |
| 回归 | 锁合入 / 发布 | 全量单元 + 按影响范围分档的冒烟（及仓库声明的 e2e / 接口）。任一层失败阻塞 |

功能做完必须达到：相关层单元全绿 + 受影响冒烟通过。新接口 / 新页面 / 新可复用模块没有对应用例，视为开发未完成。

**重构是大改动**：跨文件重命名、签名调整、抽象提取、模块拆分、公共工具迁移、DSL 或数据结构变更，无论看起来多等价，合入共享基线前必须跑回归。

前端 / 后端规范只写各端命令、产物和特有时机，不复制本表。

## 2. 影响范围分档（冒烟 / e2e）

- **全局改动或大重构**：跑全部冒烟（及仓库声明的全部 e2e）。
- **其它改动**：只跑推断受影响的剧本，并把推断依据写进测试报告或意图。拿不准按全局处理。

全局的例子：鉴权、HTTP 客户端、路由框架、设计令牌、依赖大版本、构建配置。

## 3. 用例写法（前 / 后 / e2e 共用字段）

用例正文放在各端测试目录。本文只定字段与索引，不复制自动化源码。适用场景按功能裁剪：能碰到的才写，不要为不存在的权限模型补权限用例。

每条用例（含前端组件/页面测、后端单元/接口、e2e、冒烟）至少能回答：

| 字段 | 要求 |
| --- | --- |
| 用例 ID | 稳定、仓库内唯一。已有编号则沿用，不在文档里另起一套 |
| 覆盖功能 | 指向 [功能地图](../../项目Wiki/功能地图.md) 的功能名或路由/接口 |
| 前置 | 账号、开关、服务是否已起、特性开关 |
| 测试数据 | 构造方式与隔离范围；不写真实密钥或生产数据 |
| 步骤 | 可重复的操作或调用 |
| 断言 | 可观察的期望；失败即失败 |
| 清理 | 数据、文件、会话如何收回；没有副作用写「无」 |
| 环境 | 本地 / CI / 需依赖的服务；指向 [开发指南](../../项目Wiki/开发指南.md) |
| 证据 | 报告路径、日志、截图或用例内记录位置 |

场景类型（适用才列）：正向、边界、失败 / 负向、权限（未登录、无角色、越权）。

## 4. 可靠性与隔离

- 用例必须可重复：同一提交、同一环境，两次执行结论一致。
- 不依赖执行顺序，不依赖上一条留下的脏数据。共享环境必须写进「环境」字段。
- 禁止用重跑掩盖失败：未改代码仅靠再跑一次变绿，记为失败或 flaky，不得当通过，也不得在 CI 里无限重试直到绿。
- 禁止跳过断言、捕捉后吞掉、或把超时当成功。
- 禁止用生产凭证跑本地测试。密钥不入库，见 [安全与配置](../工程规范/安全与配置.md)。

## 6. 证据与环境

- 冒烟 / e2e 执行后必须留下证据（报告目录、日志路径、或用例内「证据记录」）。没有证据的「我跑过了」不算通过。
- 测试所需进程由开发者按 [开发指南](../../项目Wiki/开发指南.md) 自行启动；启动前按该页要求重建产物，避免 stale class / stale bundle。
- 静态读过命令不等于执行成功；`last_verified` 只在真正跑过或对照过脚本后才填。
